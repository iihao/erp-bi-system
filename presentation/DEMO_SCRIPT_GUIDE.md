## 5 分钟 Demo 逐秒操作指南

### 第 1 步：系统登录（0:00 - 0:30）

**操作路径：**

1. 打开浏览器，访问 `http://localhost:3000/login`
2. 输入账号：`admin`，密码：`admin123`
3. 点击「登录」按钮
4. 等待跳转到仪表板首页

**预期效果：**
- 登录成功后页面自动跳转到 `/portal/dashboard`
- 页面顶部显示欢迎语和用户名
- 仪表板 KPI 卡片正常加载

**讲解词：**
> "接下来我将演示系统的核心功能。首先登录系统，使用 admin 账号..."

**异常处理：**
- 如果登录失败：检查后端服务是否启动，`curl http://localhost:8000/health`
- 如果页面白屏：按 F12 查看控制台报错，通常是前端资源未加载，刷新即可
- 如果跳转慢：说明"系统正在加载数据"，然后手动点击跳转

---

### 第 2 步：仪表板展示（0:30 - 1:15）

**操作路径：**

1. 在仪表板页面，手指向顶部的 KPI 卡片
2. 依次说明：总销售额、总订单数、客户总数、环比增长率
3. 鼠标指向销售趋势折线图，说明时间范围
4. 展示产品排行柱状图
5. 展示品类占比饼图
6. （可选）点击日期筛选器，选择一个日期范围，观察数据联动

**预期效果：**
- 4 个 KPI 卡片显示具体数字
- 折线图显示近 30 天的销售趋势
- 柱状图显示 TOP 10 产品
- 饼图显示各品类销售占比

**讲解词：**
> "这是系统的主仪表板，顶部展示了四个核心业务指标：总销售额、订单数、客户数和增长率。
> 中间是近 30 天的销售趋势图，可以看到销售数据的波动情况。
> 右侧是产品排行和品类占比，帮助分析销售构成。
> 所有数据支持按日期范围筛选，实时更新。"

**异常处理：**
- 如果 KPI 显示为空：数据未加载，点击刷新按钮
- 如果图表未渲染：可能是 ECharts 初始化失败，刷新页面
- 如果数据为零：ETL 流程未执行，提前准备好测试数据

---

### 第 3 步：报表浏览（1:15 - 2:00）

**操作路径：**

1. 点击左侧菜单「报表」或「销售报表」
2. 进入报表页面，展示产品排行
3. 展示品类占比分析
4. 演示日期筛选功能：
   - 选择「本月」
   - 观察数据刷新
   - 选择「上月」
   - 观察数据变化

**预期效果：**
- 报表页面展示多维度分析图表
- 日期筛选后数据联动刷新
- 图表渲染流畅，无明显卡顿

**讲解词：**
> "接下来看报表模块。这里提供了更详细的业务分析维度，包括产品排行、品类占比等。
> 通过顶部的日期筛选器，可以灵活选择分析时间范围。"

---

### 第 4 步：AI 智能问数演示（2:00 - 3:30）⭐ 重点

**操作路径：**

1. 点击左侧菜单「AI 智能问数」或导航到 `/ai-query`
2. **示例 1（简单查询）：**
   - 输入框输入：`销售额最高的产品是什么？`
   - 点击「发送」或按 Enter
   - 等待 AI 处理（约 2-3 秒）
   - 展示结果：
     - 生成的 SQL
     - 查询结果表格
3. **示例 2（聚合查询）：**
   - 输入：`上个月各品类的销售占比`
   - 等待处理
   - 展示结果
4. **示例 3（多表 JOIN，可选）：**
   - 输入：`本月消费金额最多的客户`
   - 等待处理
   - 展示结果

**推荐查询问题清单（按难度排序）：**
| 难度 | 问题 | 预期结果 |
|------|------|----------|
| 简单 | 有多少个产品？ | 产品数量 |
| 简单 | 列出所有客户 | 客户列表 |
| 中等 | 上个月销售额最高的产品 | TOP 产品 |
| 中等 | 各品类的销售占比 | 品类汇总 |
| 复杂 | 本月消费金额最多的前 5 个客户 | 客户排行 |

**预期效果：**
- AI 自动生成 SQL 并展示
- SQL 执行结果以表格形式呈现
- 整个过程在 3 秒内完成
- SQL 语法正确，结果合理

**讲解词：**
> "这是本系统的创新功能 — AI 智能问数。用户可以用自然语言提问。
> 比如'销售额最高的产品是什么？'，系统会自动理解语义、生成 SQL 并执行。
> 大家可以看到这里展示了 AI 生成的 SQL 语句和查询结果。
> 再试一个更复杂的：'上个月各品类的销售占比'，同样能正确执行。
> 目前支持多表 JOIN、聚合查询和时间表达式，准确率超过 80%。"

**异常处理：**
- **AI 响应超时（> 5 秒）：**
  - 说明"AI 正在处理，我们来看下预生成的 SQL 示例"
  - 切换到准备好的 SQL 截图或之前执行成功的记录
- **SQL 生成错误：**
  - "AI 有时会生成不完美的 SQL，我们来看一下它生成的语句..."
  - 展示 SQL，解释问题所在，说明改进方向
  - 换一个更简单的问题重试
- **网络问题（百炼 API 不通）：**
  - 提前准备 2-3 个 SQL 截图作为备用
  - 说明原理后直接展示结果截图

### 第 5 步：Metabase BI 展示（3:30 - 4:15）

**操作路径：**

1. 切换到已打开的 Metabase 标签页 `http://localhost:3001`
2. 如果未登录，输入 Metabase 账号登录
3. 展示预置的仪表板（如有）
4. 展示一个已有的报表/问题
5. （可选）快速点击「新建问题」，选择数据源，展示拖拽界面（不做完整创建）

**预期效果：**
- Metabase 页面正常加载
- 能看到预置的仪表板和报表
- 拖拽界面清晰展示自助分析能力

**讲解词：**
> "除了自研前端，系统还集成了 Metabase 这个开源 BI 工具。
> 业务人员可以通过拖拽方式创建报表，无需编写 SQL。
> 这样形成了双 BI 方案：自研前端提供固定报表和 AI 问数，
> Metabase 提供灵活的自助分析能力，两者互补。"

**异常处理：**
- Metabase 未启动：`docker-compose start metabase`，跳过此步
- Metabase 加载慢：说明"Metabase 首次加载较慢"，直接展示截图

## 演示注意事项

1. **鼠标移动要慢**：评委需要看清楚你点击了哪里
2. **不要快速切换**：每个模块停留 3-5 秒，让评委消化信息
3. **边做边讲**：操作和讲解同步进行，不要沉默操作
4. **不要展示报错**：如果有报错页面快速刷新或切换
5. **控制节奏**：5 分钟是上限，4 分 30 秒完成最佳
6. **保持微笑**：演示过程中保持自信的姿态
